## 2. 발견된 3개 버그

### Bug A — wikilink `<a>` 태그에 basePath 누락 (CRITICAL)

**증상**: `<a href="/wiki/projects/geode/concepts/geode-architecture">` 가 deployed HTML에 박힘. 사용자가 클릭 → `https://mangowhoiscloud.github.io/wiki/...` 로 navigate → **404**.

**원인**: Next.js의 `basePath: "/mango-wiki"` 는 `<Link>` 컴포넌트에만 자동 prepend. **rehype/remark가 출력한 raw `<a href>`** 에는 prepend 안 됨. `slugToHref()` 가 `/wiki/...` (basePath 없는 형태) 만 반환 → wikilinks resolver가 그대로 사용 → 모든 markdown wikilink 가 잘못된 href 생성.

**영향 범위 (2차 크롤 측정)**:

| `/wiki/projects/geode/references/blog-hub` | 168 |

본질적으로 **모든 markdown 본문 wikilink** 가 깨져 있었음 — 사이드바/그래프 (Link 컴포넌트) 만 정상이었던 셈.

**수정** (`app/mango-wiki/src/lib/vault.ts:147-156`, `wikilinks.ts:50-69,108-141`):

```ts
// vault.ts — basePath 결정 함수 (next.config.mjs 와 동일 로직)
export function basePathPrefix(): string {
  const explicit = process.env.MANGO_WIKI_BASE_PATH;
  if (explicit !== undefined) return explicit;
  return process.env.NODE_ENV === "production" ? "/mango-wiki" : "";
}

// wikilinks.ts — remarkWikilinks + remarkInlineMdLinks 안에서 basePath 주입
const BASE = basePathPrefix();
const href = hit ? BASE + slugToHref(hit.slug) : `#unresolved-${...}`;
```

`slugToHref` 자체는 변경 안 함 (Sidebar/MobileNav/GraphView 의 `<Link>` 가 여전히 자동 prepend로 작동해야 함). raw `<a>` 를 발급하는 site만 명시 prefix.

### Bug B — `raw/` 디렉토리가 public 빌드에 포함 (PRIVACY)

**증상**: `out/wiki/raw/kiki-profiles/user_*` 가 정적 export에 들어감. 즉 사용자 프로필 관찰 데이터가 public URL에서 접근 가능.

**원인**: `vault.ts:43` 의 `SKIP_DIRS = new Set(["_raw", "node_modules", ".git", ".obsidian"])` 가 `_raw` (언더바) 만 skip. 실제 vault 디렉토리 이름은 `raw/` (언더바 없음) → walker가 진입 → 모든 raw 페이지가 route로 등록.

**영향**: `kiki-profiles/`, `kiki-signals/`, `kiki-teams/`, `kiki-docs/` 의 markdown 모두가 deployed. 12개 user profile + 12개 signal observation + 2 team file + 3 docs = 약 29 개 페이지가 public 노출.

**수정** (`vault.ts:43-46`):

```ts
const SKIP_DIRS = new Set(["raw", "_raw", "node_modules", ".git", ".obsidian"]);
```

빌드 결과: 369 routes → 347 routes (raw 22개 routes 제거).

## 4. 왜 1차에서 못 잡았나 — 크롤러 한계

1차 BFS 크롤러는 `<a href>` 를 추출 후 `urljoin(current_url, href)` 로 절대 URL 만든 뒤 `mangowhoiscloud.github.io` host + `/mango-wiki/` 경로로 시작하는 것만 큐에 넣었음. 

- `<a href="/wiki/foo">` 가 *현재 페이지* `/mango-wiki/wiki/...` 에 붙으면 absolute root resolution → `/wiki/foo` (host root) → 호스트 OK 이지만 path가 `/mango-wiki/` 로 시작 안 함 → **filter out** → 큐에 안 들어감 → **404 안 잡힘**.

2차 크롤러는 같은 추출 후, **별도 basePath-less 패턴 detector** 추가:

```python
if h.startswith("/wiki/") or h.startswith("/graph") or (h.startswith("/") and not h.startswith("/mango-wiki")):
    basepathless[h].add(current_page)
```

**교훈**: BFS link checker는 *클릭 후 navigate되는 곳* 을 따라가지만, *클릭이 향하는 곳의 옳고 그름* 은 별도 lint해야 함.
